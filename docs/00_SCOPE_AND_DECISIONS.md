# 00｜需求、范围与已确认决策

## 1. 业务问题

用户经常绘制两类工作图：

1. **网络拓扑图**：交换机、路由器、防火墙、服务器、VM、IP/端口、网络连线、分组区域。
2. **业务系统架构图**：外部系统、后台平台、子模块、业务区域、数据流、控制流、包含关系。

用户希望通过**自然语言 + 节点关联关系**自动得到可编辑图纸，并在 Windows 上的 draw.io Desktop 中精修；之后还能把精修结果导回 AI 服务继续修改。

## 2. 端到端交付目标

```text
自然语言 / Graph JSON
        ↓
语义提取（LLM 可选，原始 JSON 可直达）
        ↓
GraphDocument 结构/语义校验
        ↓
ELK.js 首次布局或受控局部布局
        ↓
.drawio 原生 XML 文件
        ↓
Windows draw.io Desktop 打开 → 拖动 → 改线 → 保存
        ↓
上传最新 .drawio → 变更预览 → 合并版本
        ↓
自然语言修改 → GraphPatch → 变更确认 → 新 .drawio
```

## 3. 已确定的设计决策（不得擅自改变）

| ID | 决策 | 说明 |
|---|---|---|
| D-01 | Windows 使用 draw.io Desktop | 编辑器是用户本地程序，非服务端绘图服务 |
| D-02 | 服务端不部署 draw.io | 输出文件通过浏览器下载、上传；不自动控制 Windows GUI |
| D-03 | LLM 负责语义，不负责 XML/绝对坐标 | 防止模型直接控制图纸文件格式 |
| D-04 | ELK.js 负责首次布局 | 不自行编写完整图布局算法；局部更新保护人工布局 |
| D-05 | GraphDocument 是语义主模型 | 原始 `.drawio` XML 作为编辑后图形事实，二者版本同步 |
| D-06 | 图文件必须可编辑 | 不能把整个拓扑当成一张图片插入 |
| D-07 | 先确定性后 AI | Phase 0 无需模型和 GPU 就必须生成两类图 |
| D-08 | 增量修改需先预览再提交 | 破坏性操作要求确认、版本冲突不能覆盖 |
| D-09 | 未指定的物理连线不得推断 | 不应为了布局完整而补造事实 |
| D-10 | 未知 draw.io 内容不丢弃 | 回导应保留原 XML 或拒绝危险修改 |

## 4. 本次版本必须实现（V1）

- 文字/Graph JSON 输入；网络和业务架构两类图；最低基础形状库；节点/边/组/标签/属性。
- 结构化 JSON Schema 与语义校验；不确定关系警告。
- ELK.js 首次布局、简单局部节点插入、正交线/基本样式。
- `.drawio` XML 生成；Windows Desktop 打开/编辑/保存的人工实测。
- React 最小管理页面：生成、导入、下载、差异预览、修改指令、版本列表；**不包含图形画布**。
- FastAPI、配置化 OpenAI-compatible LLM、mock 模式、SQLite + 文件快照。
- **本系统生成图纸**经 Desktop 编辑后回导，识别位置、标题、连接端点变化，生成新版本。
- GraphPatch 原子应用、破坏性确认、人工位置保护及错误处理。

## 5. 暂不实现

- **亿图图示 EDDX**：此前只是可行性评估，未作替换决定。本版仍然输出 `.drawio`。
- PPTX/VSDX 输出；Windows 自动同步助手；浏览器内完整 draw.io 编辑器。
- 从照片/截图识别拓扑（VLM）；自动确认模糊线条；任意复杂外部 draw.io 文件无损反向解析。
- 实时多人协作、企业组织权限、云端文件同步、自动检查真实网络设备。
- Excel/CSV 导入、丰富设备图标库属于下一阶段增强，不应阻塞 V1。

## 6. 范围与验收边界

- **初次生成**：从两个不同的 JSON fixture 真正布局/生成原生 `.drawio`；样例 XML 不算实现完成。
- **Desktop 闭环**：人工移动节点、改名、改连线，保存后上传，差异能被识别并安全续编。
- **模型独立性**：禁用 LLM 时 JSON 生成仍可工作；使用 LLM 时须通过 schema 校验。
- **兼容性**：V1 只保证系统生成的单页图纸及其 Desktop 回存版本；第三方任意图纸支持度不能虚报。

## 7. 开发文档规范

本目录中的每份文件各管一件事，不重复制定同一契约：

- 字段类型以 `contracts/*.json` 为准。
- 组件与运行边界以 `01_ARCHITECTURE.md` 为准。
- 文件序列化与导入约定以 `03_DRAWIO_ADAPTER.md` 为准。
- 任务与验收分别以 `05_IMPLEMENTATION_TASKS.md`、`06_TEST_ACCEPTANCE.md` 为准。
